# DEV-014 managed lifecycle Scheduler

This isolated Terraform root declares one paused Cloud Scheduler job in the existing OrgMaster production project. It sends a bodyless POST to the fixed OrgMaster lifecycle route using an OIDC token from the existing runtime service account. Data sources verify the exact project number and immutable service-account subject; this root creates no identity, IAM binding, API enablement, service, Secret, or database resource.

The production backend example uses the existing state bucket and the dedicated dev-014/managed-lifecycle/production prefix. The copied lock file pins the provider version already locked by OrgMaster production infrastructure.

The job starts paused and is billed while paused. Terraform owns creation and the fixed template, with ignore_changes = [paused]; only the protected-source exact-job operator owns later pause/resume. The plan allows only creation or no-op; an existing no-op requires live Scheduler state/template readback. An enabled no-op also requires the current-source immutable resume receipt, actual owner intent/native migration joins and matching current job snapshot. Terraform resolves the two data sources into prior_state during planning; the gate verifies their values and full configuration set, without fabricating resource_changes read entries. Do not apply this draft until the pending fee decision and existing release conditions are satisfied.

The provider normalizes an empty Scheduler retry configuration with retry_count = 0 by removing it. This root therefore omits retry_config; the profile requires a readback effective retry count of zero. The worker's 50-second whole-cycle bound is an application contract and is not configured by this job.

The required source_revision and foundation_manifest_sha256 come from the clean official source-lock and applied foundation provider readback. Run node scripts/dev014-managed-lifecycle-plan-gate.mjs <structured-plan.json> <source-lock-gs-ref#sha256=...> <foundation-gs-ref#sha256=...> [<transition-gs-ref#sha256=...>]; the fourth ref is required only for an enabled existing no-op. The command rechecks merged source/tree, immutable bytes, exact provider/data/managed address sets, bodyless OIDC template and output binding; it never applies a plan.
